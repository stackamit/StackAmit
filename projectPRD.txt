1. EXECUTIVE SUMMARY
================================================================================

StackAmit is a comprehensive, full-stack Internship Management System designed
to bridge the gap between academic learning and industry demands. It provides a
professional SaaS platform for managing internships, trainers, students, tasks,
certificates, and real-time communication — all under one unified system.

The platform serves three distinct user roles — Admin, Trainer, and Student —
each with tailored dashboards, workflows, and permissions. It features real-time
messaging via Socket.io (WhatsApp/Telegram-style chat), email notifications via
SendGrid, cloud file storage via Cloudinary, PDF certificate generation with QR
verification, automated offer letters with an authorized signature image, a
public articles/blog system, visitor feedback capture, browser-level response
caching for fast repeat loads, and a dynamic public-facing website.
The application is deployed and live in production.

================================================================================
2. PROJECT OVERVIEW
================================================================================

2.1 Problem Statement
---------------------
- Students lack structured, industry-relevant internship programs with proper
  mentorship and certification.
- Trainers and institutions struggle to manage internship assignments, task
  tracking, and student progress at scale.
- Employers have no reliable way to verify internship certificates.
- No unified platform exists that combines internship management, communication,
  task workflows, and certificate verification.

2.2 Solution
------------
StackAmit provides an end-to-end internship lifecycle management platform:
- Admins create and manage internship programs, onboard trainers, and oversee
  the entire system.
- Trainers mentor students, assign and review tasks, and issue certificates.
- Students browse internships, apply, complete tasks, communicate with trainers,
  and earn verifiable certificates.
- Employers and institutions can verify certificates via URL or QR code scan.

2.3 Target Audience
-------------------
- Educational institutions offering internship programs
- Training organizations and bootcamps
- Students seeking industry experience and certifications
- Employers verifying candidate credentials

4. USER ROLES & PERMISSIONS
================================================================================

4.1 Admin
- Full system access and control
- Create, update, close, publish, and delete internships
- Create and manage trainer accounts (with welcome email)
- Assign students to trainers (with optional internship mapping);
  trainer capacity (maxStudents) is enforced during assignment
- View and manage all student applications (approve/reject)
- Mark approved internships as "Completed" (frees the student to apply
  again and releases one slot on the assigned trainer's capacity)
- Manage all offer letters (view, resend email with PDF attachment)
- Monitor all conversations and discussions (close/mute support)
- Manage certificates (issue, revoke, resend email with PDF)
- Moderate published articles (blog system)
- View and reply to user feedback (contact page + authenticated feedback)
- Configure system settings (company info, email, security, certificates,
  social media links including WhatsApp)
- View dashboard analytics and reports, export data to Excel
- Receive notifications for all system activities

4.2 Trainer

- View assigned students only (scope-limited visibility)
- Create, assign, and manage tasks for assigned students
- Review and grade task submissions (approve/reject/request resubmission)
- Communicate with assigned students via real-time chat
- Issue certificates for completed internships
- View dashboard with student progress and task statistics
- Toggle active/inactive status
- Receive notifications for task submissions and system events

4.3 Student
- Register with email OTP verification
- Browse and apply for published internships
- Track application status (pending/approved/rejected/withdrawn/completed)
- View assigned trainer and internship details
- View and download Offer Letter (PDF) after approval
- Complete and submit tasks (file upload, GitHub link, live URL, video demo)
- Communicate with assigned trainer via real-time chat
- Download certificates and share the public certificate link
  (native share sheet on mobile / clipboard copy on desktop)
- Write and manage articles on the shared blog (draft/published)
- Manage profile (personal info, education, skills, social links, resume)
- Receive notifications for task assignments, application updates,
  internship completion, and certificates

4.4 Public (Unauthenticated)
-----------------------------
- Browse homepage with dynamic content
- View available internships with category filtering
- Read about the platform
- Contact the organization and submit public feedback
- Browse and read published articles (blog)
- Verify certificates by certificate number or QR scan
- View shareable certificate page (/certificate/:id) without login

5. CORE FEATURES & MODULES
================================================================================

5.1 Authentication & Authorization
-----------------------------------
- Student registration with email OTP verification
- Admin-created trainer accounts with welcome email and temporary password
- JWT-based authentication with access token (15min) and refresh token (7 days)
- Role-based access control (Admin / Trainer / Student)
- Password reset via email OTP
- Force password change on first login (for admin-created accounts)
- Secure HTTP-only cookies for refresh tokens
- Token auto-refresh via Axios interceptor

5.2 Internship Management
--------------------------
- Admin creates internships with full details:
  - Title, description, category, duration (weeks + hours/week)
  - Eligibility criteria, requirements, skills, responsibilities
  - Learning outcomes, total seats, application deadline
  - Start date, end date
- Internship statuses: Published, Closed, Archived
- Public browsing with category-based filtering
- Student application with one-application-per-internship constraint
- Only one active internship at a time (pending or approved blocks new applications)
- Admin/Trainer application review (approve/reject with notes)
- Student can withdraw applications
- Seat management (total vs. filled count)
- Admin "Mark Completed" flow: sets application status to completed,
  clears student's current internship + trainer assignment, frees a trainer
  capacity slot, and notifies the student in real time

5.3 Task & Submission Workflow
-------------------------------
- Trainers create tasks with:
  - Title, description, priority (low/medium/high), due date
  - Attachments, instructions, total marks
- Students submit tasks with:
  - File attachments, GitHub repository link
  - Live deployment URL, documentation, video demo link
  - Remarks/notes
- Trainers review submissions:
  - Approve / Reject / Request Resubmission
  - Award marks, add remarks
- Task statuses: pending, in_progress, submitted, approved, rejected, resubmission_requested
- Email notifications for task assignments and submission reviews

5.4 Certificate System
-----------------------
- Unique certificate number generation (UUID-based)
- QR code generation for each certificate
- PDF certificate generation via PDFKit with professional template
- Authorized signature image centered at the bottom of the certificate
  (same server/assets/signature.png as the offer letter) with signer name
  and role beneath the rule; graceful fallback if the image is missing
- Re-arranged certificate layout: credentials band with Duration,
  Internship Period, Category and Date of Issue columns; certificate
  number + verification ID block bottom-left; QR code bottom-right
- Certificate types: Completion, Participation, Merit
- Certificate fields: student name, internship title, duration, issue date, issuer
- Public verification via:
  - Certificate number lookup
  - QR code scan (mobile camera)
  - Direct URL sharing
- Public shareable certificate view page (/certificate/:id) — no login required,
  returns only display-safe fields (no personal email/details)
- Share links built from window.location.origin so they work correctly on
  localhost during development and on the deployed production domain
- Native share sheet on mobile, clipboard copy fallback on desktop
- Certificate revocation with reason tracking
- Social sharing (WhatsApp, Twitter/X, LinkedIn, Facebook)
- Email notification on certificate issuance with PDF attached
- Admin resend of certificate email with PDF

5.5 Real-Time Communication (Discussion System)
-------------------------------------------------
- Internship-scoped conversations (tied to internship + trainer + student)
- Conversation types: Private, Group, Announcement
- Message types: Text, Image, PDF, Document, Video, Audio, ZIP, Code, Announcement, System
- Features:
  - Reply to messages (thread support)
  - Pin important messages
  - Mark messages as important
  - Edit and delete messages
  - Typing indicators
  - Online/offline status
  - Read receipts
  - Unread count tracking
  - Message search
- Admin can monitor all conversations
- WhatsApp/Telegram-style interface:
  - Chat doodle background, gradient bubbles with tails
  - Consecutive-message grouping (same sender collapsed)
  - Sender avatars + role-colored badges
  - "Today/Yesterday" date chips
  - Blue double-check read receipts
  - Floating scroll-to-latest button
  - Auto-growing pill input with inline emoji picker and attachment
- Conversation list with last-message previews, relative timestamps,
  unread count badges, and live updates via socket events
- Mobile list/chat switching with back button

5.6 Notification System
------------------------
- Dynamic notification types:
  - Task assigned, task reminder, task completed
  - Application status (approved/rejected)
  - Certificate issued
  - Internship updates (created/updated/closed/deleted)

- Read/unread status tracking
- Unread count badge in header
- Admin receives notifications for all system activities

5.7 Student Profile Management

5.11 Activity Logging & Audit Trail
-------------------------------------

  - User who performed the action

  - Entity type and ID
  - Details/metadata

  - User agent
- Recent activity feed on dashboards

5.12 File Upload System
------------------------
- Cloudinary integration for all file uploads
- Supported types: images, documents, PDFs, resumes
- Multer middleware for upload handling
- Type filtering and size limits
- Generic upload endpoint for flexibility
- Upload fields are named "file" (single) / "files" (multiple) convention

5.13 Offer Letter System
-------------------------
- Generated automatically when an application is approved
- Professional A4 PDF via PDFKit with branded header, offer details box,
  candidate information, key skills, and responsibilities
- Authorized signature image embedded above the signature line
  (server/assets/signature.png; graceful fallback if image missing)
- Offer Letter ID and date reference (SA/OFFER/xxxxxxxx)
- Emailed to the student as a PDF attachment on approval (non-blocking)
- Student download from dashboard (authenticated blob handling)
- Admin can view all offer letters and resend the email with PDF
- Mirrors the certificate PDF/email architecture pattern

5.14 Articles / Blog System
------------------------------
- Any authenticated user (student/trainer/admin) can write articles
- Article fields: title, content, cover image, tags, status (draft/published)
- Content supports Markdown (headings, lists, bold/italic, code blocks,
  quotes, links, images)
- Inline content images: authors insert an image via URL (https:// or
  site-relative) or by uploading a PNG/JPG/WebP/GIF file (Cloudinary, max
  5MB); rendered as a captioned figure on the public article page
- Access control: author manages own articles; public sees published only
- Public articles list + article view page on the website
- Shared blog pages: ArticleEditorPage (create/edit), MyArticlesPage (manage)
- Status update endpoint for publish/unpublish

5.15 Feedback System
---------------------
- Public feedback submission (contact/feedback page, no auth required)
- Authenticated feedback with user attribution
- Admin panel: list, view, reply, update status, delete, statistics
- Feedback statuses (new/replied/resolved) with admin reply tracking

5.16 Performance & Browser Caching
------------------------------------
- localStorage API response cache for relatively static GET endpoints
  (internships, articles, certificates, students, trainers, settings) with
  per-endpoint TTLs (2–10 minutes)
- Cache keys scoped per logged-in user (no cross-account data leakage)
- Automatic invalidation on successful mutations (POST/PUT/PATCH/DELETE)
  for the matching resource; binary/blob downloads bypass the cache
- Site settings persisted in localStorage (12h expiry) for instant
  public-page rendering
- Netlify cache headers: /assets/* immutable (hashed filenames),
  index.html must-revalidate (users always get fresh deploys)
- Vite manualChunks vendor splitting: large libraries (react, framer-motion,
  emoji-picker, icons, socket/axios) cache independently across deploys
- Rate limiting tuned to prevent 429 false positives during normal
  dashboard usage (see section 9.2)

------------

--------

6.14 ActivityLog

6.15 Setting
------------

6.16 Assignment
---------------
- trainerId (ref: Trainer), studentId (ref: Student)

6.17 Article
-------------

6.18 Feedback

8.1 Connection & Authentication
--------------------------------
- JWT-based Socket.io authentication middleware
- Automatic reconnection on disconnect
- User online/offline status tracking

8.2 Events
----------
Client -> Server:
- joinConversation      - Join a conversation room (also marks messages read)
- leaveConversation     - Leave a conversation room
- sendMessage           - Send a real-time message (REST is primary path)
- typing                - Start typing indicator
- stopTyping            - Stop typing indicator
- messageEdited         - Edit a message
- messageDeleted        - Delete a message
- togglePin             - Pin/unpin a message
- toggleImportant       - Mark/unmark message as important

Server -> Client:
- newMessage            - New message delivered (with conversationId)
- messageEdited         - Message edited notification
- messageDeleted        - Message deleted notification
- messagePinned         - Message pinned notification
- messageImportant      - Important flag notification
- messagesRead          - Read receipts update
- userTyping / userStopTyping - Typing status update
- userOnline            - User came online
- joinedConversation    - Room join confirmation
- notification          - Real-time notification pushed to user room
- error                 - Socket-level authorization/mute errors

Rooms: user:<userId> for notifications, conversation:<conversationId> for chat.
Message reads are applied automatically when a user joins a conversation room.

9. SECURITY MEASURES
================================================================================

9.1 Authentication & Authorization
-----------------------------------
- JWT access tokens (15-minute expiry)
- JWT refresh tokens (7-day expiry, HTTP-only secure cookies)
- bcryptjs password hashing (12 salt rounds)
- Role-based access control middleware
- Password change enforcement for admin-created accounts
- Email verification via OTP for student registration

9.2 Data Protection
--------------------
- Helmet.js for HTTP security headers
- CORS configuration with allowed origins (CLIENT_URL allow-list)
- Rate limiting, separated by purpose:
  - General API limiter: 1000 requests per IP per 15 minutes
    (skips /api/auth/* and health check)
  - Authentication limiter: 100 failed attempts per IP per 15 minutes
    (skipSuccessfulRequests; /auth/refresh-token fully exempt so
    automatic token renewal never returns 429)
- Input validation via express-validator
- MongoDB injection prevention via Mongoose
- XSS protection via input sanitization

9.3 File Upload Security
--------------------------
- Multer type filtering (whitelist allowed MIME types)
- File size limits
- Cloudinary server-side upload (no direct client uploads)

9.4 Session Management
-----------------------
- Refresh token rotation
- Token blacklist on logout
- Secure cookie flags (httpOnly, secure, sameSite)

9.5 Audit & Monitoring
-----------------------
- Activity logging for all system actions
- IP address and user agent tracking
- Error logging with Morgan
